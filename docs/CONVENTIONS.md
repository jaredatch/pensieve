# CONVENTIONS.md — Pensieve

Code style, naming, and organization — only the decisions an agent could otherwise get wrong, and the places where this project diverges from the macOS/Swift module's defaults. The Executor reads this before writing code; the Planner keeps it honest. Standard Swift style is assumed and not restated.

## 1. Language baseline & strictness

- **Swift 5.10**, macOS **14.0** deployment target (`project.yml`). **Not** Swift 6, and strict concurrency is **not** enabled. The macOS/Swift module lists "Swift 6 + strict concurrency / async-everywhere" as a default — Pensieve has not adopted it yet. Write to 5.10 reality; promoting to Swift 6 is a deliberate future decision requiring a written rationale, not something to slip in mid-stage.
- No force-unwrapping (`!`) in production code; tests may force-unwrap a known fixture invariant.
- `guard let` for early returns over nested `if let`.

## 2. Naming

- The `Skill` model field is **`skillDescription`**, not `description` — `description` collides with `CustomStringConvertible`/`NSObject`. Any new model field that shadows a stdlib/runtime name gets the same disambiguation.
- File name = primary type it contains (`SkillStore.swift` → `SkillStore`). A protocol and its concrete impl live in **one file** (`FileServiceProtocol` + `FileService` in `FileService.swift`), with `// MARK: - Protocol` / `// MARK: - Implementation` sections.
- Tests: `{TypeName}Tests.swift` under the `PensieveTests/` directory matching the code's layer — `ParserTests/`, `ServiceTests/`, `ViewModelTests/`, `ViewTests/` (view-adjacent logic, plus hosted tests that mount a production view in an `NSWindow` to prove lifecycle behavior, such as `InstalledSkillHistoryHostTests`), `UtilitiesTests/`, `AppTests/` (runtime and test-host guards); shared fixtures and test doubles in `Fixtures/`. A large suite splits by concern into `{TypeName}Tests+{Concern}.swift`. Test methods are `func test…()` (XCTest — see `docs/TESTING.md`).

## 3. File & module organization

- **Three-layer pattern, no exceptions:** `Models/` (`@Model` plus the plain value types beside them: `PlatformTarget`, `SkillScope`, `CursorAdapterConfig`) → `Services/` (protocol + impl) → `ViewModels/` (`@Observable`) → `Views/` (SwiftUI). New code goes in the matching directory. A large type splits by concern into `{Type}+{Concern}.swift` extension files in the same directory (`SkillInstallService+Vendor.swift`, `ManifestService+Snapshot.swift`, `AppRuntime+DeployIndex.swift`); SwiftLint's default length limits are in force and are the usual trigger.
- Two files sit beside the layers: `Pensieve/AppRuntime.swift` (the process-scoped `@MainActor @Observable` runtime that builds the `ModelContainer`, the long-lived view models, the scheduler, and the coordinator — `docs/ARCHITECTURE.md` §2) and `Pensieve/PensieveApp.swift` (the `@main` entry, scenes, and menu-bar commands). `Pensieve/Utilities/` holds SwiftUI-free helpers used across layers: `PathConstants` (the SwiftUI-free path/config source, compiled into the daemon) re-exported as `Constants` (which adds the `Spacing`/`CornerRadius` design tokens), `DeployIndex` (the in-memory index of `deploy-state.json`), `SkillBundleInventory` (the SwiftUI-free walk over a skill's directory), `ListRows` (the Mail-anatomy row model and pure per-section row builders), `AppSignal`, `RelativeTime`, `GitHeadStamp`, and `DogfoodMode`. Put a pure, testable mapping there rather than in a view.
- Views are grouped by feature subdirectory — `MainWindow/` (window, navigation, sidebar, list row, detail column, tag views), `SkillViews/` (with `Editor/` for the web editor host and `Detail/` for the tabbed detail's header, strip, and tabs), `PlatformViews/`, `ImportViews/`, `InstallViews/`, `ProjectViews/`, `CategoryViews/`, `ScenarioViews/`, `MachineViews/`, `SyncViews/`, `SettingsViews/` — **one feature per file.** Pensieve does **not** co-locate view + view-model + preview in one file (the module suggests it); view models live in `ViewModels/`, with two sheet-scoped exceptions that sit beside the view they serve (`PlatformViews/DeployIntentModel.swift`, `ScenarioViews/ScenarioDetailModel.swift`). Pure presentation value types (`DetailContentSnapshot`, `ProjectSkillsSnapshot`, `SkillHistoryPresentation`) may sit beside their view. Follow the existing split.
- A new service ships **both** the protocol and the concrete implementation; inject the protocol, never the concrete type.
- Before you move a method that a check binds to its file, grep the check's anchor block. Moving code to satisfy a check is right only when placement is the requirement (PLAN-26 / 26.2).

## 4. UI / framework patterns

- **`@Observable`, never `ObservableObject`/`@Published`.** View models are `@Observable final class`, passed to views as `@Bindable`.
- View models **hold service protocols** (constructor-injected, with a concrete default for app use — e.g. `init(skillStore: SkillStoreProtocol? = nil, fileService: FileServiceProtocol? = nil)`), so tests inject stubs.
- View models do **not** store the `ModelContext` — it is **passed into each method** that persists (`createSkill(..., context:)`, `deploy(..., context:)`). Views get the context from `@Environment(\.modelContext)` and `@Query`. Keep this pattern; don't stash a context on a VM. (The one existing exception is the sheet-scoped `SyncSetupModel`, constructed per connect flow with the context it needs; don't add another.)
- SwiftData reads in views use `@Query`; the container is built once by `AppRuntime.makeContainer` and attached to the main window and Settings scenes in `PensieveApp.swift`.
- **Pure SwiftUI by default; AppKit only as a narrow bridge.** The bridges that exist, each justified in its own doc comment: the sidebar (`SidebarOutline`, an `NSViewRepresentable` over an `NSOutlineView` source list), the tag editor (`TagTokenField`, an `NSViewRepresentable` over an `NSTokenField`; its coordinator owns the editing baseline — SwiftUI has no token field), the editor host (`MarkdownEditorWebView`, an `NSViewRepresentable` over a hardened `WKWebView` — §14), `NSOpenPanel` in `AddProjectSheet` and `ContentView.importFromFolder` for directory selection, the window-close veto (`WindowCloseGuard`, a delegate proxy over the main window — SwiftUI has no close hook), and `PensieveAppDelegate` for process lifecycle. New AppKit use is allowed only where a SwiftUI wrapper visibly diverges from the tier-1 Apple-app pattern, needs a justifying comment, its own selection-bridge tests, and stays minimal.
- **Body reads no disk.** A SwiftUI `body` never calls a filesystem-reading method (`platformVM.isDeployed`, a `FileService` probe); it reads a value loaded once off the render path (`DetailContentSnapshot`, `ProjectSkillsSnapshot`) or observable state (`PlatformViewModel.deployIndex`). The same rule bars anything that blocks or shells out from `body` or a computed property it reaches: a subprocess `waitUntilExit` inside the render pass pumps a nested run loop and crashes, it does not hang.
- **Name the control before tuning it.** A tier-1 look (Finder's sidebar, Mail's list) is a specific AppKit or SwiftUI control; establish which, and whether SwiftUI's wrapper renders it identically on the current OS (probe with a bare sample app if unsure), before touching a property. Where the wrapper visibly diverges, use the AppKit control (PLAN-28 retired two imitation commits). → playbook macos-swift module (EVO-56).
- **App-wide shortcuts live in the menu bar's command groups**. A `keyboardShortcut` on a button inside a toolbar `Menu` is never a key equivalent, and on the macOS 14 baseline a `Commands` body does not observe `@Observable` reads, so an item whose enabled state tracks a model wraps in a `View`. A command that a *view* observes through a notification (`.importSkills`) is received by every main window — macOS window tabbing opened a second one even with New Window retired, until `WindowPolicy` turned tabbing off — so the observer still acts only when its window `appearsActive` (PLAN-30 / 30.2: two choosers per ⌘⇧I). → playbook macos-swift module (EVO-56).
- **A focused scene value outlives a sheet, so gate destructive commands on `controlActiveState`.** A menu item enabled only by a published action stays live while that window's own sheet holds the keyboard, and its key equivalent outranks a text field inside the sheet (PLAN-34 / 34.2-m: ⌘⌫ typed in New Skill's name field raised the delete confirmation for the skill behind it). Publish `controlActiveState == .key` as a second focused scene value and require it — `appearsActive` stays `true` under the window's own sheet, which is exactly why `.importSkills` uses it and a delete command cannot.
- **Adds read `addsFenced`; edits read `libraryUnavailable` / `isWriteFenced`.** A control that creates a new entity — a skill by any route, a project, a category, a scenario — disables on `SkillLibraryViewModel.addsFenced`, and its funnel guards on it too; a control that changes an existing row reads the older fence.
- **A bridge coordinator's state gets a lifecycle table.** An `NSViewRepresentable` whose coordinator keeps state (an editing baseline, a session, a cache) has that state's lifecycle written in its plan as a table — seeded where, refreshed on which callback, what happens on end-editing, termination, deletion, and a SwiftUI update that changes no input — each row a criterion or a gate clause (PLAN-30 / 30.1: two halts and two refreezes for a baseline seeded on the wrong callback and never refreshed after `.adoptStored`).

## 5. Logging

- The structured-logging seam is `Pensieve/Utilities/AppSignal.swift`: `enum AppSignal` names the signals (`app.launched`, emitted once from `PensieveApp.init()` through the injectable `LaunchSignaler`, whose default sink is `os_log` on the `com.jaredatch.pensieve` / `signals` log; and `skill.changed_externally`, for external `SKILL.md` edits observed by `FileWatchService`). `AppSignalTests` asserts delivery through an injected recording sink. Extend the same pattern as behavior-acceptance needs new signals. (The headless smoke gates on a clean build, not on the signal — `docs/TESTING.md` §6.)
- Convention going forward: subsystem `com.jaredatch.pensieve`, dot-named events (`app.launched`, `skill.deployed`, `import.completed`); make the sink injectable so a test can assert delivery. Behavior tests assert on these signals (see `docs/TESTING.md` §2). Define each new signal name here as it's added.

## 6. Error handling

- Error typing is uneven today: the git, sync, credential, install, and update services throw **typed `LocalizedError`** enums with a user-readable `errorDescription` (`LinkError` includes the offending path; also `GitError`, `SyncError`, `CredentialError`, `SkillInstallError`, `SkillUpdateFlowError`, `UpdateCheckError`, `MachineStateError`); `SkillStore` throws a plain `SkillStoreError: Error`; `FileService` propagates Foundation/`NSError` directly. View models `catch` whatever propagates and set a `String? error` for the UI — they don't crash or swallow. Prefer a typed `LocalizedError` for **new** services (don't claim the codebase is uniformly typed — it isn't yet).
- Parsers **degrade, not throw**: `SkillParser.parse` returns an all-body result when the YAML frontmatter is absent, unparseable, or refused by `CheckedYAMLLoader`; admissibility is a *separate* strict check, `ParsedSkill.hasRequiredFrontmatter` (`name`+`description` both non-empty), not "did it parse." Keep new parsing tolerant in the same way, and gate on the required check where a complete skill is needed.
- No silent empty `catch {}` in services.

## 7. Async / concurrency

- Leaf services are **synchronous and throwing** (local filesystem and git ops). The one async layer is resident orchestration: `AppRuntime` and `SyncScheduler` are `@MainActor`, `SyncCoordinator` is a `@ModelActor`, and runtime entry uses detached tasks so synchronous git and SwiftData work stays off the main actor (`docs/ARCHITECTURE.md` §4 Concurrency). Don't invent `async` seams below that boundary.
- **Probes are tri-state.** A guard may treat a probe's answer as load-bearing only when the probe distinguishes its own failure from both of its answers; a nil/bool-conflating probe (`remoteURL`, PLAN-24's rev-8 `hasLocalBranches`) is fail-open for whichever consumer skips on the value the failure maps to. Make the signal tri-state and route the unknown case explicitly per consumer (PLAN-24).
- **A lock-guarded observable property is `@ObservationIgnored`.** An `@Observable` stored property that a `body` reads and a background thread mutates under a lock is `@ObservationIgnored`, with an observed main-thread signal beside it for the views that show the derived state (PLAN-33 batch review finding 1: `lastWrittenBody` under `fingerprintLock` completed an ABBA deadlock with SwiftUI's update lock on the first `body` evaluation).
- Don't assume a VM is `@MainActor` — the sync, install, update, provenance, conflict, and login-item models are; the library, platform, import, and category/machine models aren't. Adopting `@MainActor` on the view-model layer wholesale is a future decision, not a per-stage drive-by. Bridge any legacy callback with `withCheckedContinuation`.

## 10. Git hygiene & linting

- **Default branch is `master`** (the remote's `HEAD` → `origin/master`). Never push to `master` directly.
- Commit messages: **Conventional Commits** (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`). Under the ExecPlan loop, a stage commit's message **also** carries the stage reference `PLAN-NN / NN.X` so the docs-commit guard can pair it with changes to the work log and plan file (`docs/TESTING.md`, the ratchet guard). Outside a stage, the ratchet's other forms: `PLAN-NN / review` for a review verdict or fix, `PLAN-NN / close` for the close, `PLAN-NN / patch` for a bounded change to a closed plan's surface, `PLAN-NN / fix` for a fix batch that spans Stages, built in a fresh Codex session (`script/drive-stage.sh --fix` — playbook 0.19), `PLAN-NN / refreeze` for a re-stamp (the ratchet's refreeze-trace leg requires it, with the `.acceptance-amends` line staged — playbook 0.16), else `note:` opens the subject. Stage explicit paths, never `git add -A` (untracked scratch must never enter a commit).
- Branch naming: `feature/…`, `fix/…` for ad-hoc work; `plan-NN/stage-N-<slug>` for ExecPlan stages.
- **SwiftLint is wired as a real gate** through `script/lint.sh`, which regenerates the project and runs `swiftlint --strict` with whatever SwiftLint is on `PATH` (no version is pinned; it falls back to `swift-format lint`, then to a printed notice, when neither is installed). The tracked `.swiftlint.yml` scopes linting to `Pensieve` and `PensieveTests`, excludes build outputs, and only tunes rules that encode project conventions (`line_length` 130, `function_parameter_count` 6, `redundant_discardable_let` off). New code must pass the wrapper cleanly.

## 13. Subprocess & credentials (PLAN-08)

The app shells out to git and handles an HTTPS token. Two rules are load-bearing security boundaries — treat them like the `FileService` chokepoint:

- **Subprocess = args as an array, never a shell string.** Any subprocess (today only `GitService` over `/usr/bin/git`) sets `Process.arguments` from a `[String]` array and `Process.executableURL` to an **absolute** path (`/usr/bin/git`) — never `/bin/sh -c "…"`, never a string-interpolated command. Array-passing removes the shell-injection surface, but it does **not** stop *option* injection: git (and many tools) parse a leading-dash or `--upload-pack=<cmd>`-style positional as an option they may **execute**. So any op passing a **user-supplied remote/path positional** must put a `--` end-of-options terminator immediately before it (see `GitService.clone`/`ls-remote`). A `--` protects the *argument*, not what git parses *inside* it: a stored ref becomes a refspec (`*:refs/…/*` survived argument separation and asked the remote for every branch) and a stored path becomes a pathspec (`skills/*` selected sibling skills), so a stored ref passes Git's ref-name rules in process before any subprocess and a stored path is always a `:(literal)` pathspec (PLAN-35 `InstallRelativePathPolicy`, `GitService+UpstreamHistory`). Build the **child environment explicitly** for a Finder/Spotlight launch (which inherits neither the login-shell PATH nor the ssh-agent socket): augment `PATH` with the standard locations, set `GIT_TERMINAL_PROMPT=0` so a TTY-less op fails fast instead of hanging, pass `SSH_AUTH_SOCK` through, and **strip any inherited variable the app owns** (the app-owned `GIT_ASKPASS`/`PENSIEVE_GIT_*`, plus — PLAN-10 — the full inherited git-behavior-override family that would otherwise redirect the subprocess: `GIT_SSH*`/`GIT_PROXY_COMMAND`/`GIT_EXTERNAL_DIFF`/`GIT_CONFIG*` + indexed `GIT_CONFIG_KEY_*`/`GIT_CONFIG_VALUE_*`/`GIT_ALTERNATE_OBJECT_DIRECTORIES`/`GIT_NAMESPACE`/`GIT_TRACE*`, while deliberately **preserving** the hardening `GIT_CONFIG_NOSYSTEM`) before setting it, so a no-credential op can't ride a stale parent value or an attacker-planted override. Validate an untrusted remote against a **transport allowlist** before it reaches the subprocess: PLAN-10 centralized this in **`RemoteURLPolicy`** — a single admission point shared by connect (`SyncSetupModel.parseRemote` delegates to it) and a **sync-time re-validation** of the stored `.git/config` `origin` (`SyncEngine` re-checks before every network-touching op, so a hand-tampered origin is rejected with the *same* strength as connect) — accepting https/ssh/scp-style only and rejecting `ext::`/`fd::` remote-helper syntax (git would *execute* it), a leading `-` (bare or bracketed IPv6), https-userinfo, and an interior newline.
- **Secrets live in the Keychain + the child environment, never argv or disk.** A credential (an HTTPS PAT) is stored only in a **Pensieve-namespaced Keychain item** (`kSecClassGenericPassword`, service `<bundle-id>.git.<host>` — `com.jaredatch.Pensieve.git.<host>` in Release, `com.jaredatch.Pensieve.debug.git.<host>` in a Debug build, so the two never share a credential; the GitHub install token uses the `<host>#install` slot — never the broad `kSecClassInternetPassword`-by-server class, whose delete could wipe a foreign credential) and reaches the subprocess only through the **child process environment** (invisible to `ps`), consumed by a secret-free `GIT_ASKPASS` helper. Never put a secret in `Process.arguments`, in a URL (`user:tok@host`), in `.git/config`, or in any file the app writes — including error/log strings. A helper script that reads the secret from env is fine; a helper that *contains* the secret is not.

## 14. Non-interactive git & inert untrusted-content rendering (PLAN-09)

Two more load-bearing security rules join §13:

- **Git must be non-interactive — it can never block on an editor.** Beyond `GIT_TERMINAL_PROMPT=0` (§13), `GitService.childEnvironment` sets **`GIT_EDITOR=true`** and **`GIT_SEQUENCE_EDITOR=true`**, so a `rebase --continue`/`--skip` (or any op that would open `$EDITOR` or the interactive-rebase todo) exits immediately instead of hanging a TTY-less GUI process forever.
- **Synced/historical content is UNTRUSTED — render it inert, never through a web/JS context.** Content pulled from a remote another machine wrote (a conflicting skill body, a diff side, a `git show` of a past version) must render only through **inert** SwiftUI `Text` (monospaced, for the diff) or structural MarkdownUI `Markdown(_:)` (for a preview) — which execute nothing. Such previews must **NEVER** reach the CodeMirror editor's **`WKWebView`** (`MarkdownEditorWebView`), `loadHTMLString`, or any HTML/JavaScript-execution surface, where a hostile body could run code; a skill's canonical body — one a sync pull wrote included — reaches the editor only as a marshalled string through the hardened bridge, never as HTML. The resolution **write sink** is likewise path-guarded (`validatedWorktreePath`: reject absolute/`..`/control-char/symlink-escape — including the leaf — and, PLAN-10, any symlinked **non-leaf** component before every write/delete, closing the in-root `skills/<slug>` symlinked-directory write-through; the conflict path originates only from git's `conflictedFiles`, which PLAN-10 enumerates with `-z` (NUL-delimited) so an embedded-newline path stays one exact entry). This is one facet of PLAN-10's broader canonical-store invariant — *Pensieve never reads, writes, or deploys through a symlinked `skills/<slug>` dir* (see `docs/ARCHITECTURE.md` §4 Security posture for every enforced sink).

## 15. Canonical skill-dir guard — one C7 primitive (PLAN-11)

The **C7 invariant** — never read, write, deploy, or ingest through a symlinked or path-traversing canonical `skills/<slug>` directory — has exactly **one** enforcement primitive: the pure resolver **`SkillStore.safeSkillDirectory(slug:base:fileService:) -> String?`**. It returns the safe `<base>/<slug>` path, or `nil` when `slug` is empty / contains `/` / is `.`/`..`, or when `<base>/<slug>` is a symlink or realpaths outside `<base>`. Every canonical-slug sink **calls it and branches on the result — never open-code an `isSymlink`-only check**.

- **Keep each caller's control flow around the `nil`.** The sinks have three shapes: **throw** (`SkillStore` body sinks via the `validatedSkillDirectory` wrapper; `PlatformViewModel.deployOne`), **return 0** (`Skill.estimatedTokens`), and **skip-and-preserve + warn** (`StoreRebuildService.rebuildSkills` keeps `filePresentSlugs.insert(slug)` + `continue`; `StoreMigrationService.migrateSkill` keeps `return false`). A throw at a skip-and-preserve sink regresses the PLAN-08 row-wipe-on-a-glitch fail-safe — this is why the primitive is a pure resolver, not a bare `throws`.
- **Pass `base` explicitly** — `root + "/skills"` where the store root is a parameter (`StoreRebuildService`/`StoreMigrationService`), `Constants.pensieveSkillsDir` where it is fixed (deploy/token). The resolver never hardcodes the base.
- **Adding a new sink means calling `safeSkillDirectory`.** A sink that doesn't is visibly guardless in review. **Exception:** `SyncEngine.validatedWorktreePath` is a *different* validator (arbitrary multi-component git-relative paths, leaf-vs-non-leaf symlink semantics) and is deliberately **not** folded in — do not route it through this primitive.

## 16. Shell scripts — bash 3.2 and BSD tools

The wrappers, guards, and every frozen `Verify:` block run under macOS's `/bin/bash` 3.2 and BSD userland (CI's runner too). Four rules, each earned by a proof that lied:

- **BSD `sed` silently ignores GNU-only forms** (`0,/re/`) and leaves the file untouched, so a "red" proof over an unmutated tree proves nothing. Land mutations with a tool that reports presence (a Python edit, `perl -pi`) and `grep -c` the mutated text before trusting the red (PLAN-18 / 18.1a; PLAN-26 / 26.5).
- **bash 3.2:** guard empty-array expansion with `${arr[@]+"${arr[@]}"}`; no `mapfile`, no associative arrays.
- **A load-bearing check under `set -o pipefail` must be pipe-free.** `printf "$big" | grep -q` SIGPIPEs when `grep` exits at the first match, flips the pipeline status to 141, and `|| fail`-style wiring then silently skips exactly the oversized input the guard exists to catch. Capture to a variable or file first, or use a herestring (`grep -q <<< "$big"`).
- **Run the wrapper gates (lint / test / smoke) serially.** Concurrent runs race XcodeGen's `Pensieve.xcodeproj` write (`NSCocoaErrorDomain Code=516`) and fail spuriously at project generation.

→ playbook macos-swift module (EVO-56).

## 18. Docs voice — who each doc is for

**The human-facing set** — `README.md`, `docs/GETTING-STARTED.md`, `CHANGELOG.md`'s release sections — is written for a person: conversational and concise, a working example over a paragraph of rules, no `file:line` or `DEC-NN`/`PLAN-NN` citations in user prose, no method vocabulary. It gets the voice pass (the humanizer skill) as a checked step at every plan close that touched it and before every release.

Issues and comments on GitHub belong to this set too. They're written for contributors and maintainers, and they get the voice pass every time.

**The reality docs** — `ARCHITECTURE.md`, `CONVENTIONS.md`, `SPEC.md`, `GLOSSARY.md`, `TESTING.md` — are agent-facing and **state the present**: no "as of PLAN-NN", no shipped / not-shipped residue, no change narration. User-visible changes belong in `CHANGELOG.md`; a reality doc that narrates its own past is stale the day after. Dated research inputs and older logs are kept in the private project records.

Both kinds follow the same basics: short paragraphs, one idea per sentence, and the actor named.
