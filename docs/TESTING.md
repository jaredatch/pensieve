# TESTING.md — Pensieve test strategy

How work is verified. The stronger and faster these checks, the longer an agent can run unattended. Stack commands live in the `macos-swift` module and the `script/` wrappers (PLAN-01); this file is the *strategy*.

## 1. The test hierarchy

The suite is **XCTest** only. Its size is the committed `.test-count` — the ratchet's floor (§5, §7), bumped with every test added — not a number kept here. Tests come in these flavors:

- **Unit (pure logic, no I/O)** — the default and majority: parsers and serializers (`ParserTests/`), pure view-model queries and row builders (`SkillListQuery`, `ListRows`), reconciler and policy logic against stubs.
- **Filesystem-integration** — exercise the real filesystem through a temp directory (`LinkServiceTests`, `CursorCompilerTests`, the store/manifest/rebuild tests). These create a unique temp dir in `setUpWithError` and remove it in `tearDownWithError`. **Never touch a real user directory in a test.**
- **Git-integration** — `GitServiceTests`, the sync-engine and install/update tests run real `/usr/bin/git` against bare repositories created in a temp dir and reached over `file://`. No test opens a network connection.
- **Behavior-via-log** — `AppSignalTests` asserts the `os_log` signal emitter through an injected sink (CONVENTIONS §5). New observable-behavior acceptance criteria should grow a signal + a test.
- **View-adjacent logic** (`ViewTests/`) — the sidebar selection bridge (`SidebarOutlineControllerTests`), diff and history presentation, import results. There are **no snapshot tests**; add them with an explicit precision policy if/when the view layer earns it. Hosted tests (`InstalledSkillHistoryHostTests`, the `SkillDetail*` layout tests) mount the production view in an `NSHostingView`, and the History ones press buttons they find through the accessibility tree. That tree doesn't reach every control: the menu-bar menu's plain SwiftUI Buttons (`PensieveMenuBarView`) expose no accessibility node in the test host, only its AppKit-backed Toggle does. Test such a control's decision on the model property it reads, and leave its rendered state to a manual gate (PLAN-41 / 41.2-c17). Hosted SwiftUI bitmap and PDF captures also return blank pixels in the test host, even for a plain red view. Test the model or image provider and leave on-screen display to a manual gate. Offscreen `ImageRenderer` checks must assert visible pixels before comparing captures; two blank images can compare equal.

For offscreen preview comparisons, rendered text allows at most 4 per RGBA byte; decoded images stay exact, and both require equal dimensions and visible pixels.

Not present: **network-integration** tests. When one is needed, tag it (§4).

## 2. Acceptance ↔ tests

Each ExecPlan Stage's Validation & Acceptance is phrased as observable behavior and carries an executable, self-gating `Verify:` block (the command exits non-zero when the behavior is absent — see the Playbook `protocol/verification.md`). Where the behavior is in-app, the block runs through a `script/` wrapper and asserts on a build result, a test result, or an `os_log` signal — not on "the code was added." Signal scheme: subsystem `com.jaredatch.pensieve`, dot-named events (`app.launched`, …).

## 3. Mocks / fixtures

- Services are tested against their **protocols**; tests inject the real `FileService` over a temp dir (the default style) or a purpose-built double. There is no single shared mock layer: `FileServiceProtocol` doubles are written per test file for the one failure they need (`ThrowingWriteFileService`, `LockAssertingFileService`, `LeafRejectingFileService`, …), and the reusable ones live in `*TestDoubles.swift` / `*TestSupport.swift` files beside the tests that share them (`LinkServiceTestDoubles`, `SkillInstallTestDoubles`, `PostSyncConvergenceTestSupport`, `Fixtures/DeletionTestSupport`). Reuse an existing double before writing another.
- A view model that reconciles concurrent async work for one key is tested with a **sequence harness**. `UpstreamHistorySequenceHarness` holds every await point (disk load, read, probe, local measurement, persist) and releases them in a chosen order, and a generated test runs every reachable order with its counts pinned. Its waits are bounded by wall-clock time (`TestWait`), never by yield counts. Reuse it before writing another; PLAN-39 spent eight review rounds on races that one ordered sweep would have found.
- File fixtures live in `PensieveTests/Fixtures/` (`sample-skill-*.md`, `sample-claude-skill.md`, `sample-cursorrule.mdc`). Keep new fixtures there.
- Create test temp paths through `TestTemporaryDirectory.path` or `.url` (enforced by `lint.sh`). `test.sh` supplies a fresh root under TestRuns, deletes it on completion, and prunes interrupted runs. The test host bounds Git discovery at that root. This keeps fixtures and sibling lock files out of the shared macOS temp folder. Foundation ignores `TMPDIR`; Xcode runs use the system temp folder. Tests that need the real macOS alias or a short socket path use `.systemPath`, with a comment explaining why and cleanup for everything they create.
- A **novel test-safety mechanism** (a sandboxing double, a containment guard) ships with a **written contract** in its doc comment: the protocol surface it intercepts, the failure mode it enforces, and its deliberate exclusions. Reviewers judge against the stated contract instead of re-deriving the guarantee each pass — PLAN-22's `LinkServiceCanonicalDirectoryFileService` took a three-round hardening chain to converge, and the written contract is what ended it.
- A fixture that **stubs a production helper** (a shell function, a tool such as `hdiutil`) leaves that helper untested. Pair the stub with one test that runs the real helper against the real tool, and make the stub fail where the tool fails. PLAN-46's DMG mount check passed every release test behind a `test -d` stub and never matched a real mount, since macOS lists the resolved `/private/var/…` path (round 4). Then a detach stub that succeeded on a never-mounted path hid a defect in the cleanup trap (round 5).
- When production gains a **defaulted path parameter** (a constructor default resolving to live user state), audit **every pre-existing construction** of that type in the test target and inject explicit temp/neutral paths. A new default can silently repoint old tests at a developer's real data — PLAN-22 22.5's `ImportScanner.grokSkillsDir` default would have sent three pre-existing tests scanning the real `~/.grok/skills` without their hermeticity edits.

## 4. Test selection & tagging

- `script/test.sh` runs the full suite over `xcodebuild test`; `script/test.sh --filter Foo` runs a subset, where `Foo` is an XCTest identifier. A name with no `/` is prefixed with the `PensieveTests/` target, so `ClassName` works. A name with a `/` is passed as written, so a single test is `PensieveTests/ClassName/testMethod`: `ClassName/testMethod` names a target that doesn't exist and matches nothing (PLAN-36 / 36.1's first blocks). The wrapper refuses a filter that matches zero tests with a non-zero exit, so a misspelled filter cannot pass vacuously. Every run prints `PENSIEVE_TEST_COUNT=<n>`, which the ratchet compares against `.test-count`. Every run first takes the machine's test lock (`lockf`), so a second run from any checkout waits in line instead of starving the first. The suite runs in parallel, one test class per worker. A parallel run prints no `Executed N tests` line, so the wrapper reads the count from the run's result bundle (`xcresulttool`). A passing run whose count it can't read fails. A failed run keeps its result bundle under `DerivedData/FailedRuns/` (the newest five) and prints each failed test with its message, so a failure that doesn't reproduce can still be read afterwards with `xcresulttool` (#61).
- No tags yet. The moment a network test exists, tag it (`.network` or an XCTest skip-guard keyed to an env var) and exclude it by default — never open a network connection from an untagged test.

CI also runs the public hygiene self-test and workflow checks in its existing build job. Run them locally with `./script/public-hygiene.sh --self-test` and `ruby script/workflow_self_test.rb`. The workflow checks cover secret scope, the release condition, permissions, action pins and triggers. Use `actionlint .github/workflows/ci.yml .github/workflows/release.yml` to check workflow syntax.

## 5. Flaky-test policy & the ratchet

A flaky test is a bug, not noise to suppress. The standing rule (enforced by `script/ratchet.sh`, PLAN-01):

- A previously-passing test that fails is a **regression** — investigate to root cause. **Never** delete, comment out, `XCTSkip`, or `.disabled` a test to restore green.
- Disabling a test is a **reviewed** decision: an entry in `docs/test-allowlist.md` naming the test, the reason, the follow-up, and why the skip was approved. When working under a plan, record the skip in that plan’s Decision Log too. Removing a test on purpose, its contract kept by another, lowers the floor with `script/ratchet.sh --lower <n> --reason "<why>"`; the ratchet refuses a floor lowered by hand (playbook 0.30). The skip-marker guard fails the build on any unlisted `XCTSkip(If|Unless)?`, `.disabled(`, or `@Test(... .disabled` **added in a test file** (paths under a `*Tests/` dir or a `*Tests.swift` file — a skip marker only has meaning in a test target); the **test-count floor** (`.test-count`) is the backstop that catches a commented-out test the grep misses.
- **Scope (was a prose trap, narrowed in PLAN-04 follow-up).** The guard scans the *staged diff* but now only the added lines **of test files**, so naming a marker token in its call form (the `XCTSkip` family, or the SwiftUI `.disabled` modifier, with an open parenthesis right after) in app code, a doc, a log entry, a plan, or a code comment **no longer self-blocks the commit** — the idiomatic SwiftUI view-disable modifier is free in app code. The one residual case: the same token *inside a test file* (including a comment there) is still checked, so keep the name and its parenthesis apart in test-file prose. Originally surfaced the day the hooks went live (PLAN-01 Stage 01.3+) and over-broad until the PLAN-04 close narrowed it.
- **CI replay (PLAN-18).** GitHub Actions now replays the commit-time ratchet story for each commit in the pushed or PR range through `script/ci-replay.sh`, then runs the normal suite and headless smoke on the range head. This catches hook-bypassed commits in CI instead of trusting a developer's local hooks. The proof pattern is git plumbing only: synthetic commits are built with `git hash-object`, a temporary `GIT_INDEX_FILE`, and `git commit-tree`, so no local hook is disabled and no branch is polluted. `script/ci-replay.sh --self-test` runs that proof hermetically (a throwaway repo under `mktemp`, every per-commit rule both ways).
- **Workspace guards (2026-09-08, playbook EVO-52).** Two more ratchet checks make the scratch-directory convention structural. *Close ritual* (`--commit-msg`): a subject carrying `PLAN-NN / close` — bare, `docs:`-prefixed, or the branch merge — is rejected unless the **staged** review manifest (the index copy) carries its `## Tracked files` inventory, every path that inventory marks `tracked:` is in the index (unstaged or ignored evidence is named — `git add -f` it), the inventory lacks nothing the guard's own dry run (below) inventories (a manifest staged before a second `--apply` promoted more files is stale — re-stage the review dir), the archive inventory is non-empty with its `.tar.zst`/`.tar.gz` beside it, the plan scratch directory is gone (the proof `--apply` finished — an `UNRESOLVED` cite keeps the dir), `script/tmp-tidy.sh --plan PLAN-NN --dry-run` exits 0 (the citation proof, re-run by the guard rather than trusted from the checklist), and `script/tmp-tidy.sh --check` is clean ("close without tmp-tidy"). *Citation drift* (pre-commit, cheap and static): a line **added** to a root or `docs/` `.md` may cite only an open plan's scratch (open = its row in the plan index, read from the git index, is not `complete`/`superseded`), a plan placeholder, or the configured resume note; a legacy bare path or a closed plan's scratch is named and the commit refused — cite the tracked review path or the archive instead, and write another repo's scratch with its repository name. Only cites new to the diff count (an in-place edit of an old paragraph carries its cites through); private logs, archives, research and review manifests are out of scope by design. CI mirrors the tracked half of both (the MANIFEST with its inventory, every inventoried path in the commit's tree; the cites via the same `ratchet.sh --cite-check` path against each commit's own plan index) — the `.list`, the dry-run, and `--check` read gitignored paths, so the local hook is their only gate. The stage-claim matcher pairs the plan *file* by its plan number, never an edit under the review folder. The docs-commit guard's non-stage forms are `review`, `close`, `patch` (a small change on a closed plan's surface), `refreeze`, `fix`, and `note:`, each bounded by a non-alphanumeric, so `patchwork` or `review2` is not a form. The skip-marker guard captures `git diff`'s listing before filtering: a git failure exits 1, never reads as "clean". Proven both ways in both `--self-test`s.

- **The ratchet is the playbook kit's (2026-09-10, playbook 0.16 → 0.16.1).** `script/ratchet.sh`, `script/refreeze.sh`, `script/ci-replay.sh`, the hooks, and the extractor are the kit's copies, configured by `script/ratchet.conf` (the config sets the resume-note path; the Swift regexes, the allowlist path, and the `PENSIEVE_TEST_COUNT` marker are the module's defaults). Every guard is one decision function in `ratchet.sh`; `ci-replay.sh` sources the same file and replays the same functions per commit (its env is `RATCHET_CI_SKIP_DEFAULT_MERGE_HEAD`). New legs since the hand-hardened 0.15 copy: the acceptance hash is recomputed from the **index** copies of the ledger, the plan, and the extractor, and digests the extraction's raw bytes (a hand-made `awk | shasum` stamp reproduces — all 28 did at the swap); a **secrets** leg refuses secret-shaped files and credential-shaped added lines (`# ratchet:allow-secret` marks a fixture's fake); a **refreeze trace** leg requires the `PLAN-NN / refreeze` subject and a staged `.acceptance-amends` line for any changed stamp, and the plan-status change in the same commit for a first stamp; `pre-push` refuses a `master` push without `RATCHET_ALLOW_PUSH=1` (the maintainer's variable, never an Executor's) and any non-fast-forward push. A **criteria** leg (playbook 0.20) refuses a builder commit (a stage claim, `fix` or `patch`) that changes an unstamped plan's `## Validation and Acceptance`, so the Planner commits criteria and `Verify:` blocks as `note:`. Every script has `--self-test`, both ways, on bash 3.2 and 5.

## 6. Headless / smoke

`script/build_and_run.sh --headless` **builds and links** the app for an agent/CI smoke check and prints `SMOKE OK` — build+link is the reliable unattended signal for a macOS GUI app. It does **not** assert a real headless window launch: under XCTest the main `WindowGroup` can be launch-suppressed, so window-presentation assertions may never fire (the module's hazard). The `app.launched` `os_log` signal (PLAN-01) is the in-app seam for *future* behavior tests — asserted via an injected sink in a unit test, **not** by the headless wrapper. Prefer directly-unit-testable seams over "present a window and measure."

The XCTest suite still launches Pensieve as its app host, but the split entry point in `PensieveMain` sends that process to `PensieveTestHostApp`. The test host is inert and never bootstraps `AppRuntime`, so it cannot start the scheduler, coordinator, or launch reconciliation. This guard does not sandbox test code: individual tests that use live default paths can still write to `$HOME`. Moving those remaining writes to explicit temporary paths is a separate backlog concern.

The test bundle's load hook sets FileService's shared folder-check deadline to 30 seconds before cases run, allowing for suite load. The app keeps its two-second deadline. Tests of that bound call `ProjectDirectoryProbeDeadline.useAppDeadline(in:)`; XCTest teardown restores the host deadline even after a failure. Cases run serially within each host, and parallel workers have separate registries. Isolated registries keep the app's two-second default.

## 7. Coverage

Directional, not a vanity gate. The committed `.test-count` floor (PLAN-01) ensures coverage only ratchets up, except a deliberate `--lower` with its reason (§5); a percentage coverage floor is deferred until the count floor proves too coarse (per the Playbook, adopt on evidence).

## 8. Dogfood mode — a Debug build against throwaway data

`script/dogfood.sh <Debug Pensieve.app>` runs the app against `~/PensieveSandbox/home` under two OS levers and no app code: `CFFIXED_USER_HOME` re-roots every Foundation home API (plain `$HOME` is ignored by all of them on macOS 26), and a `sandbox-exec` profile denies filesystem writes outside the fake home, kernel-enforced and inherited by git. Its tolerances: the per-user temp, cache, and `DARWIN_USER_DIR` trees and a few `/dev` nodes stay writable (Foundation needs them at launch), the launcher's own log is written by the shell outside the fence, reads are not fenced at all, and network stays open unless `--offline`. The script self-tests the fence before each launch and refuses a non-Debug bundle. Debug builds carry the bundle identifier `com.jaredatch.Pensieve.debug`, so their UserDefaults, Keychain items, and Sparkle state are separate from the released app's even without the script; the script stages a re-identified copy (`com.jaredatch.Pensieve.dogfood`) so sandbox runs do not share prefs with the live-data dev build either, and `--reset` wipes that domain; with `PENSIEVE_DOGFOOD=1` (set by the script) Sparkle is not constructed and the legacy-agent migration is not installed, the two launchd/XPC paths the fence cannot see. Before launch the script gives the fake home its own throwaway keychain (`Library/Keychains/dogfood.keychain-db`, password `dogfood`), makes it the fake home's default and whole search list, and checks that the real default and search list don't name it, so a token saved in a sandbox run never reaches the real keychain and macOS never raises its "Keychain Not Found" dialog. `--reset` wipes the fake home (that keychain with it), the dogfood prefs domain, and any dogfood Keychain items an older run left in the real keychain for a true first run; `--offline` denies network. From a Mac without the toolchain, `script/pull-dev-build.sh --host HOST --sandbox [--reset] [--offline]` does the pull and the handoff.

This is the sanctioned way to drive the GUI with cua-driver on a live machine, and the way to run the empty-store manual gates. Launch only through the script: `open`, Finder, and Xcode Run go through LaunchServices and drop the fence. The XCTest host is unaffected: it still runs against the real home (§6).
