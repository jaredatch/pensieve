# GLOSSARY — Pensieve

Domain and technical vocabulary, so a stateless agent reads plans and code without guessing. (ExecPlan-method terms — ExecPlan, Stage, Planner/Executor/Reviewer, tier — are defined in the Playbook, not repeated here.)

| Term | Definition | Source |
|---|---|---|
| **Skill** | A markdown instruction file for an AI coding agent (conventions, review checklists, workflow rules). The unit Pensieve manages. | `docs/SPEC.md` |
| **`SKILL.md`** | The standard filename for a skill body, inside a per-skill directory. The Agent Skills open standard. | agentskills.io |
| **Canonical store** | `~/.pensieve/skills/{directoryName}/SKILL.md` — the one source-of-truth copy of every skill body. Everything else is deployed from it. | `Constants.pensieveSkillsDir` |
| **`directoryName` / slug** | The lowercased, hyphenated, collision-suffixed folder name for a skill; the join key between the on-disk body and the SwiftData `Skill`. | `Services/SkillStore.slugify` |
| **Deploy** | Make a skill visible to a specific agent, by symlink or compiled file, user-wide or per-project. | `Services/LinkService`, `CursorCompiler` |
| **Adapter** | The per-agent deploy mechanism. Standard-markdown agents get a symlink; Cursor gets a compiled `.mdc`. | `docs/SPEC.md` "Platform Adapters" |
| **`PlatformTarget`** | The agent enum (`claudeCode`, `grok`, `cursor`, `codex`, `openClaw`, `hermes`); `usesSymlinks` selects symlink vs compile. | `Models/PlatformTarget.swift` |
| **Scope** | `user` (deploy to user-wide paths, active in every project) or `project` (deploy to a project's paths only). App state, not stored in the file. | `Models/SkillScope`, `docs/SPEC.md` "Skill Scopes" |
| **Cursor `.mdc`** | Cursor's rule file: YAML-ish frontmatter (`description`, `globs`, `alwaysApply`) + body, generated by `CursorCompiler`. | `Services/CursorCompiler.swift` |
| **Required frontmatter** | The `name` + `description` YAML pair every admissible `SKILL.md` carries; `ParsedSkill.hasRequiredFrontmatter` gates import preservation, migration, and rebuild admission. A body-only file parses but is not a skill. (The earlier TOML `format_version` marker is superseded.) | `Services/SkillParser` |
| **Cursor adapter config** | Per-skill Cursor settings (`description`, `globs`, `alwaysApply`) stored as JSON `Data` on the `Skill`; the only per-platform config any agent needs. | `Models/Skill.cursorConfig` |
| **`DeployRecord`** | A SwiftData row logging one deploy/remove (skill, platform, target path, timestamp, content hash). For history and freshness. | `Models/DeployRecord.swift` |
| **Token budget** | One advisory skill-size budget, default 5,000 tokens. Counts the `SKILL.md` body without frontmatter at characters/4. Overview warns only for local deployments, user-wide or in registered projects. Never blocks a deploy. | `Services/TokenCounter` |
| **Fan-out** | Deploying one canonical skill to many agents (and, in BETTER, re-deploying on each machine after sync). | `docs/SPEC.md` |
| **Manifest** (BETTER) | The portable schema-v5 overlay synced with the canonical store: skill bookkeeping, category definitions, and per-entry deploy intent; its `projects.yaml` is the constant `projects:`. Observed machine state, project identities included, lives separately under `machines/`. | `ManifestService` |
| **Machine identity** | A stable canonical UUID generated for this installation and stored outside the synced tree at `~/Library/Application Support/Pensieve/machine-id`. It addresses machine state and deploy intent; deleting it creates a new identity. | `MachineIdentity` |
| **Machine state file** | One machine's read-only published snapshot at `~/.pensieve/machines/<machine-id>.yaml`: display name, app version, publication time, detected agents, project identities, and realized deploys. Each machine writes only its own file. | `MachineStateService` |
| **Deploy intent** | A synced request for a skill to be deployed to an agent on a named machine, either for the whole Mac or for a project identity key. `manifest/deploys/<machine-id>/<slug>.yaml` carries its user-wide platform list and optional project entries; deleting the last scope retracts the file. | `MachineDeployIntent` |
| **Intent ledger / `IntentAssignment`** | This Mac's private SwiftData record that a user-wide or project-scoped artifact was realized from deploy intent. A project row carries the local project id, so `IntentReconciler` removes only the exact intent-owned artifact when intent is retracted. | `IntentAssignment`, `IntentReconciler` |
| **Convergence pass** | The ordered local repair after launch ingestion or a successful resident sync: deploy self-healing on every success, then category and intent reconcilers on a fresh SwiftData context — always after launch ingestion, and after a resident sync only when the cycle ingested a new HEAD. | `PostSyncConvergence` |
| **Deploy index / `deploy-state.json`** | `deploy-state.json` under app support is this Mac's recorded set of realized deploys (one record per artifact path, never synced; `DeployStateStore`). `DeployIndex` is `PlatformViewModel.deployIndex`, the in-memory, observable copy the list rows and the Skills filter read instead of the filesystem; it is rebuilt after every in-app deploy/remove, launch backfill, and convergence pass, and reports `.unavailable` — never empty — when the file cannot be read. Where it disagrees with the filesystem-backed Deployments tab, the tab is the truth. | `Utilities/DeployIndex.swift` |
| **Mail-style list row** | The one row anatomy every middle-column section uses: a bold title with a secondary trailing text (Mail's date column) and an optional glyph before it, then up to two more lines; no leading icon, no status dot. `ListRowModel` is the value, `ListRows` the pure per-section builders, `ListRowView` the SwiftUI. Mail's measured 3pt line gap and 5pt padding override the 4pt grid here. | `Utilities/ListRows.swift` |
| **Tag** | A free-form label on a skill, edited as tokens in the detail's metadata area (`TagTokenField`, with completion from the tags in use) and stored in the manifest overlay, never written into `SKILL.md` by Pensieve; an import seeds them from the source's frontmatter and normalizes them, and a source `tags:` entry stays in the file as authored (PLAN-42) (`TagTokens.normalize`: trimmed, case-insensitively deduplicated, sorted). Tags is also a sidebar section whose entities are the tags in use. | `Views/SkillViews/TagTokenField.swift`, `Utilities/TagTokens.swift` |
| **Import from Folder…** | The + menu and File › ⌘⇧I command that imports one chosen folder — a skill, or a folder of skills, never deeper — refusing anything that lands in or passes through the store (`ImportScanner.scanFolder` / `isInsideStore`). Find Skills on This Mac… is the machine-wide scan (Claude Code, Grok, Cursor, Codex). | `Services/ImportScanner.swift` |
| **Section / entity selection** | `SidebarSection` is what the sidebar selects (Skills, Projects, Categories, Tags, Machines); `EntitySelection` is the instance chosen in the middle column; the detail column describes it. The sidebar never grows one row per entity. | `Views/MainWindow/Navigation.swift` |
| **Upstream History** | The origin repository's commits to an installed skill's path, read on demand over git through the install path's validated remote and credential — a bounded scratch fetch, no clone kept, the result held for the session by `UpstreamHistoryViewModel` and keyed by skill, origin, and upstream head. The tab shows each commit's hash, date, author, subject, files and lines changed; marks the **installed** row (the newest path commit at or before `installed_commit`, a tri-state when the window has not reached it) and the **available** ones; and shows **local edits** measured against the installed baseline. Authored and imported skills keep the sync-repository History instead. | `docs/ARCHITECTURE.md` § The upstream History read |
| **View Changes window** | The one window besides the main window. It previews one skill's pending update: every changed file with its line counts, and a unified diff with invisible characters marked. It never writes: its Update hands the skill to the Updates sheet, the only update apply owner. | `Views/InstallViews/ViewChangesWindow.swift` |
| **Draft** (editor) | The editor's unsaved text: an entry in `SkillLibraryViewModel.drafts` keyed by slug, opened at the first keystroke that differs from the file and closed by typing back, Save, Revert, or the skill's deletion. Dirty is *measured* against the file's fingerprint (the store's canonical body), never remembered, so a file that catches up reads clean. It reaches disk only on Save — the Save button, `Cmd+S`, File › Save — and every way out of an edited skill passes `confirmLeaving`, the detail's tab switch, file pulldown, and rendered toggle included; Delete asks its own confirmation. `confirmLeaving` raises the stock unsaved-changes sheet (`UnsavedChangesAlert`: Save / Don't Save / Cancel). A draft dies with the process. | `docs/ARCHITECTURE.md` § Edit / preview |
| **AppKit bridge** | A narrow `NSViewRepresentable` hosting the AppKit control a tier-1 Apple-app pattern is made of, used only where the SwiftUI wrapper visibly diverges, such as the sidebar's `NSOutlineView` source list (`SidebarOutline`) or the main window's close veto (`WindowCloseGuard`). `docs/CONVENTIONS.md` §4 lists every one. | `docs/CONVENTIONS.md` §4 |
| **Quiet machine state** | `machines/<id>.yaml` is rewritten only when its parsed known fields differ from the composed state (`MachineState.contentEquals`, ignoring `published_at`), so an idle sync cycle creates no commit. `published_at` means "last state change", never liveness; the UI says "Last updated". | `MachineStateService` |
| **In-place adoption** (fresh-store connect) | How a fresh Mac joins an existing sync remote: the launch-created empty manifest scaffold is adopted in place — initialized, fetched, materialized from `FETCH_HEAD`, and given its first local branch — rather than cloned over or swept. Admission requires positive proof of the virgin scaffold (or Pensieve's own interrupted adoption) and empty synced SwiftData families; anything else is refused with nothing mutated. | `SyncSetupModel.adoptInPlace` |
| **Quarantine** | Two fail-closed holds. A **store quarantine** is launch reconciliation refusing to ingest or auto-prompt import when a configured store's local-branch signal is not definitely born (or a probe threw). A **row quarantine** is a deleted skill whose files are gone but whose SwiftData row could not be saved away: the row stays listed and fenced until a retry proves absence or a relaunch rebuilds. | `LaunchReconciler`, `AppRuntime.storeQuarantined`; `SkillLibraryViewModel.pendingRowCleanup` |
| **Proof-gated deletion** | Skill deletion removes only symlinks whose target proves Pensieve ownership, on the agents detected at launch and in registered projects, then retracts the slug's deploy intent and ledgers in one transaction. Compiled Cursor rules stay. | `PlatformViewModel.removeAllDeploys` |
| **Small change / sprint** | Work that lands without a plan; a **sprint** is small changes on one surface on a `sprint/<topic>` branch, with one entry in the work log and one review. The older term **Route A** means no product change. **Route B** means a design, UI or UX change. | — |
| **Tier-1 / tier-2 reference** | The design authority order: Apple's stock apps (Finder, Mail, Notes, Photos) are binding conventions; Mimestream and Chops are secondary craft references; every other cited app is background only. | `docs/DESIGN-PROPOSAL.md` |
| **Dogfood mode** | A Debug build launched by `script/dogfood.sh` against a throwaway home under `CFFIXED_USER_HOME` and a `sandbox-exec` write fence, re-identified as `com.jaredatch.Pensieve.dogfood`; `PENSIEVE_DOGFOOD=1` (`DogfoodMode.isActive`) stands down Sparkle and the legacy-agent migration. Debug builds themselves carry the `com.jaredatch.Pensieve.debug` identity. | `Utilities/DogfoodMode.swift`, `docs/TESTING.md` §8 |
